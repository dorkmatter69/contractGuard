## Acceptance design check

Domain v2 binds chain ID, deployed escrow address, protocol name/version. Typed Acceptance binds exact task ID, mandate hash, artifact commitment, validator/version commitment, authorized EOA validator address, per-task settlement nonce and deadline. Task IDs also encode payer and monotonic funding nonce. Terminal escrow state prevents a second release/refund. A valid signature cannot select a different recipient or amount: these are immutable funded terms.

Tests passed for wrong signer/artifact/settlement nonce, cross-task/contract/chain replay, malformed/high-s signatures, revoked validators, expiry refunds, duplicate release/refund, cross-task reentrancy, failed token-transfer rollback, inexact funding and unauthorized withdrawal. The cross-layer test compares the Python-signed message hash with the deployed Solidity digest.

Validator self-revocation is per escrow and permanent. It blocks future release and new funding for that EOA; pending funds return to payer only after expiry. It is not a general validator registry, multisig administrator or rotation mechanism. Off-chain mandate revocation stops new acceptance preparation; it cannot invalidate a previously signed attestation already outside the control plane. On-chain key self-revocation or signature expiry governs those signatures.
